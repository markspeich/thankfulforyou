# Amazon Production Listing Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make production Amazon listing creation safe for arbitrary Etsy listings, reconcile migration history, and deploy the verified feature without creating another real Amazon listing.

**Architecture:** Persist operator-confirmed Amazon production facts separately from imported Etsy source facts on each listing draft. Treat edits as revisioned draft changes that invalidate prior production validation, then build the product-only Amazon payload and content hash exclusively from the saved values. Keep existing approval, duplicate, uncertain-outcome, explicit-confirmation, and signed-image safeguards.

**Tech Stack:** Node.js ES modules, browser JavaScript, Vitest, Playwright, Supabase Postgres migrations/RPCs, Vercel.

**Spec:** `docs/requirements.md` section `Production Amazon listing integration`

## Global Constraints

- Facts confirmed for Etsy source `4357670739` are scoped to that product and must not become defaults for unrelated imports.
- Production submissions use `LISTING_PRODUCT_ONLY` and must not submit price, offers, or inventory.
- Creation requires a saved current revision, approved copy and selected images, successful validation for the same revision/content hash, and explicit in-app confirmation.
- Accepted and uncertain submissions must remain protected from duplicate replay; submission history must not be cleared.
- Amazon images must use seven-day signed HTTPS URLs from the private `amazon-listing-delivery` bucket.
- Every waiting operation uses a working dialog; failures use a dismissible keyboard-accessible red error dialog and preserve edits.
- Do not create another real Amazon listing during production verification.
